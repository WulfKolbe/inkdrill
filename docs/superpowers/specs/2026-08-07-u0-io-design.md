# U0 `io.py` — PNG ingest

Design doc. Written 2026-08-07, before implementation, per the `units.md`
convention that a contract precedes its unit.

## Why this unit exists

The package had no way to turn a rendered page into an `InkMask`. `raster.binarize`
accepts a raw greyscale buffer and nothing in the package produced one. U9, U10
and U11 all need pixels, and U4 wants real pages for a smoke test beyond its
synthetic fixtures.

Numbered **U0** rather than inserted at U4: it depends on nothing and feeds U2,
so "foundation, below U1" is where it belongs, and renumbering U4–U14 would
break the `see docs/units.md U1/U2/U3` cross-references already written into
the `space`, `raster` and `sweep` docstrings.

## Scope limit, stated up front

**Ghostscript `png16m` output only** — IHDR exactly `(8, 2, 0, 0, 0)`: 8-bit,
truecolor RGB, deflate, adaptive filtering, non-interlaced. This mirrors U9's
"embedded, non-Type-3, outline fonts only": a narrow contract with the limit
named rather than a general implementation that is mostly untested.

Anything else raises `UnsupportedPNG` naming the exact IHDR tuple found. 16-bit,
palette, greyscale, alpha and Adam7 interlacing are all out of scope and must
fail loudly, never mis-decode.

Rejecting *greyscale* input while producing greyscale output looks backwards and
is deliberate: this unit's job is to read what this one device writes. A
greyscale PNG would be easy to support and is still refused, because accepting
an untested input path is how a decoder quietly returns a wrong image. Widening
the contract is a decision to make with evidence, not a convenience to slip in.

All five scanline filters are implemented regardless of what the corpus
contains, because libpng's adaptive heuristic may select None or Average on
content not yet sampled.

## Throughput, measured not asserted

**Superseded — see `docs/units.md` §3 for the measured figures.** The
4.94 Mpx/s neutral-path figure below came from a single Paeth-heavy
outlier page and does not represent the median; the later, larger
measurement in `docs/units.md` found a median of 24.1 Mpx/s with a wide
page-to-page spread. Left below unedited as a dated record of what was
known at design time.

| Path | Throughput | 38.9 Mpx page |
|---|---|---|
| Naive per-byte unfilter | 1.20 Mpx/s | 32.3 s |
| Channel-slice + SWAR (neutral path) | 4.94 Mpx/s | 7.9 s |
| Full 3-channel + luma (colour path) | ~1.6 Mpx/s | ~24 s |
| `sweep`, existing U3 | 19 Mpx/s | 2.1 s |
| `iter_runs`, existing U2 | 105 Mpx/s | 0.4 s |

Decode remains the slowest stage at ~4× the sweep. Stopping here is deliberate:
the residual cost sits in Paeth rows, whose predictor depends on bytes just
produced and is irreducibly sequential, and U7/U8 band parallelism addresses
page latency generally.

### The SWAR fast path

Elementwise `(a + b) mod 256` across a whole scanline, without numpy and without
a Python loop:

    low  = (A & 0x7f7f…) + (B & 0x7f7f…)      # no carry crosses a byte
    high = (A ^ B) & 0x8080…
    out  = low ^ high

Three CPython big-integer operations at C speed replace ~2400 interpreted
iterations. This covers the Up filter — 75.8% of rows. Sub rows use
`itertools.accumulate`; Paeth and Average keep an explicit loop.

Verified byte-identical to the naive reference decoder on a real 8.56 Mpx page.

### Channel independence

Every PNG filter references bytes at `bpp` stride within its own channel, so the
three channels are independent chains. `row[0::3]` is a C-speed slice that
isolates one, and unfiltering it alone is correct — with `bpp` collapsing to 1 in
the sliced domain. This is where the 3× comes from.

## The neutrality problem and its resolution

Ghostscript writes R == G == B for typical text pages, which would let us decode
one channel and skip the other two. But ~7% of corpus pages carry real colour
figures. Taking the red channel there would render red ink near-white and blue
ink near-black — silently wrong, and wrong in exactly the region a later unit
would care about.

**Resolution: an exact, cheap probe, then a two-path decode.**

Because filtering is per-channel, a neutral source image produces a *filtered*
stream that is also neutral, for every filter type, by induction on rows. So
neutrality is decidable on the raw inflated bytes with no unfiltering:

    s = row_bytes_without_filter_tag
    neutral_row = (s[0::3] == s[1::3] == s[2::3])

Two C-speed slice comparisons per row.

- **Verified**: 16/16 agreement with ground truth from a full unfilter, including
  a known colour page correctly identified.
- **Cost**: 22.6 ms/page against a ~1700 ms decode — 1.3% overhead.
- **Exact, not sampled** — it inspects every row, so it cannot miss a colour
  region the way a sampled check could.

Given the probe result: neutral pages take the one-channel SWAR path; colour
pages take a full three-channel decode with Rec.601 luma
(`0.299 R + 0.587 G + 0.114 B`). The common case stays fast and the uncommon
case stays correct. `PngImage.neutral` reports which path ran.

## Contract

    read_png(src: bytes | str | PathLike) -> PngImage

    @dataclass(frozen=True, slots=True)
    class PngImage:
        width:   int
        height:  int
        gray:    bytes           # len == width * height, row-major
        dpi:     tuple[float, float] | None   # from pHYs, None if absent
        neutral: bool            # True if the source was R==G==B everywhere

    load_mask(src, *, threshold=128, ink_is_dark=True) -> InkMask

`read_png` returns **greyscale bytes, not an `InkMask`**. That composes with the
existing `raster.binarize(gray, width, height, …)` rather than duplicating it,
and leaves the threshold decision where U2 already owns it. `load_mask` is a thin
convenience over the two, and is the only place this unit imports from `raster`.

`pHYs` is parsed rather than skipped: it carries the dpi that U1's `SpaceGraph`
needs for the pt↔px edge, and discarding it now would mean re-reading every file
later.

Errors: `UnsupportedPNG` (IHDR out of scope), `CorruptPNG` (bad signature, bad
chunk CRC, truncated stream, inflate failure, IDAT length not matching
`height * (width * 3 + 1)`). Both subclass `ValueError`.

## Guarantees

    G1  multi-IDAT: all IDAT chunks are concatenated before a single inflate
    G2  every chunk's CRC-32 is verified; a mismatch raises CorruptPNG
    G3  len(gray) == width * height, exactly
    G4  the fast path is byte-identical to the naive reference decoder, for
        every filter type and both neutrality paths
    G5  filtered-stream neutrality == decoded-image neutrality (the induction
        claim the two-path decode rests on)
    G6  an IHDR outside the stated scope raises UnsupportedPNG naming the
        tuple found; it never returns a mis-decoded image
    G7  dpi is a (x, y) pair when pHYs is present with unit specifier 1
        (pixels per metre), converted as ppm * 0.0254; it is None when pHYs
        is absent or carries unit specifier 0 (aspect ratio only, no
        physical scale). It is never silently defaulted to 72 or 300.

## Testing

The house pattern is an independent oracle rather than recorded output — U3
checks its components against a separate flood fill. Here:

- **The naive per-byte decoder is the permanent oracle.** It lives in the test
  module, is written for obviousness rather than speed, and the fast path is
  asserted byte-identical to it. This holds G4 directly.
- **G5 gets its own test**, on synthetic images built to be neutral and built to
  be non-neutral, under each filter type — the claim is load-bearing and an
  inductive argument is not a test.
- Hand-built minimal PNGs exercising each of the five filters, constructed
  in-test with `zlib` so no binary fixtures enter the repo.
- A multi-IDAT file, split mid-scanline.
- A corrupt CRC, a truncated stream, a bad signature.
- Each rejected IHDR variant: 16-bit, palette, greyscale, alpha, interlaced.
- `pHYs` present and absent.
- Stride and edge cases: a 1×1 image; a 1-pixel-wide image, where the Sub and
  Paeth `a`/`c` terms are always zero; a 1-pixel-tall image, where the Up and
  Paeth `b`/`c` terms are always zero; and an even/odd width pair, since the
  SWAR path builds its masks from `width` and a parity error there would
  corrupt exactly one edge column.

**Corpus test, opt-in.** A separate test decodes a sample of real pages from
`~/pdfdrill-library` and asserts `sweep` runs clean on them. Gated behind an
environment variable so the default suite stays hermetic, fast, and runnable on
a machine without the library. The default suite must never depend on files
outside the repo.

## Out of scope

- Writing PNG. Read-only unit.
- Any format other than PNG. If PGM/PBM ingest is wanted later — and
  `-sDEVICE=pgmraw` would be dramatically faster to read, needing no inflate and
  no unfilter — it is a separate contract, not an extension of this one.
- Colour output. This unit produces greyscale; colour-aware analysis is not a
  planned unit.
- Rendering PDFs to PNG. `pdftoppm` and Ghostscript are external tools invoked
  by hand; shelling out is not part of any package contract.
