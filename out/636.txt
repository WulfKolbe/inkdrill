THE HARNESS GAINED THE GUARD I NEEDED TWICE

`apply_last` took the last occurrence of the anchor, which the
docstring justified as "the live sweep -- _sweep_reference is the
earlier copy". That is necessary and NOT sufficient, and it bit me
twice while writing steps 0 and 1: `uf = _UF()` ... `cycles_of = {}`
and `for r in runs:` are verbatim identical in both functions, so an
anchor ending inside the oracle mutates the oracle. It presents as
seven unrelated tests erroring on a `NameError`, which reads like a
broken edit rather than a mutated oracle.

`apply_last` now refuses an anchor landing inside `_sweep_reference`'s
body.

  NOT "before `def sweep(`" -- MY FIRST ATTEMPT AT THE GUARD WAS THAT,
  AND IT REFUSED M1 IMMEDIATELY. M1, M11 and M12 mutate `_UF`, which
  is defined before the oracle, so the whole M series would have been
  locked out. The rule is the oracle's BODY, bounded by the next
  top-level `def`.

Both sides of the refusal are checked, since a guard tested only by
its raise can be made unconditional and still pass:

    anchor unique to the oracle          REFUSED
    anchor in the live sweep             accepted
    anchor in `_UF`, before the oracle   accepted

And the hazard is not hypothetical -- one shared docstring line occurs
twice in the file today.

ONE MUTANT IS DELIBERATELY ABSENT, AND THE DOCSTRING SAYS SO

`moms_of[rn] = moms_of.pop(rp)` -> `moms_of[rn] = moms_of[rp]` on the
ATTACH path. Step 1 proved it an equivalent mutant by digest -- 27
fixtures x 4, 40 random masks, a real 15.5 Mpx page, byte-identical --
because `rp` has just become a child and a union-find root never
becomes a root again, so nothing can read the stale entry.

It is UNKILLABLE. Adding it would fail the gate forever, and someone
reading the CR's list will be tempted to add it, so the reason it is
missing is written into the harness docstring beside the two families
rather than left in a report. It is not free: it leaks one entry per
root-move, 739 stale against 421 live on p1, so `pop` stays and the
cost is visible only in step 5's memory number.
