STEP 4 -- the explicit case dispatch on the number of parents
=============================================================

Change (inkdrill/sweep.py)
--------------------------
The edge loop no longer treats every parent alike.

  nadj == 0   BIRTH. The only place a counter pair is created.
  nadj >= 1   FIRST parent, handled OUTSIDE the loop: this edge can
              NEVER close a cycle, because `nid` was created this
              iteration and has not been unioned, so `rn == rp` is
              impossible. No root comparison, and `nid`'s counts are 0
              by definition rather than by lookup.
              -> this is the 86-91% case, and it is now the cheap one.
  k in (pi+1, pj)  FURTHER parents: the only place a CYCLE can occur.

The `adj` list is no longer built at Capture.NONE: the touching runs are
the slice [pi, pj) of `prevline` and the ids are read back by index. The
two-pointer scan is written out twice, once appending to `adj` for the
event path and once bare, rather than branching per step -- a first
version used one scan plus a list comprehension and made Capture.GRAPH
1.5% SLOWER, which is why it is written this way.
